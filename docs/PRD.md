## 1. 一句话定位

**《猫狗性格志》：30 题，给你的猫或狗一份会随时间变化的性格档案**，
并把「两只宠物能不能处得来」「它这半年变了没有」变成可以计算的答案。

## 2. 反定位：我们明确不是什么

这一节先写，因为它决定了后面每一个取舍。

| 我们不是 | 理由 |
|---|---|
| **宠物版 MBTI** | E/I、S/N、T/F、J/P 是「人怎么想」，不是「猫怎么行为」。这个映射在概念上就不成立，不是换个文案能救的。 |
| **拟人化萌宠测试** | 「如果你是一只猫」测的是**用户自己**，不是用户家的猫。SBTI / CBTI 走的是这条路，我们不走。 |
| **兽医工具 / 行为诊断** | 涉及疼痛、疾病、应激病理的判断一律不做，只做「转介去问专业人士」。见 §9。 |
| **宠物社交社区** | 不做动态、不做关注、不做评论区。 |
| **纯娱乐玩票** | 维度有论文出处、结果可复测、算法开源可查。这是它和「玩票」的分界线。 |

## 3. 问题陈述

主人对毛孩的困惑，集中在三件事上，而现有产品只解决了第一件：

1. **「它为什么这样？」** —— 已解决。所有竞品都给描述、给标签、给相处建议。**这一层已经饱和，不要指望在这里赢。**
2. **「我和它合不合适？」** —— 半解决。竞品给「主人×宠物契合度」，但那是**拿人的 MBTI 去对宠物的类型**，两个不同物种的量表直接相减，方法上站不住。
3. **「它变了没有？」** —— **几乎无人做**。而这恰恰是行为学里证据最扎实的部分：性格有稳定成分，也有年龄驱动的轨迹（狗的沉稳度随年龄上升、大胆度随年龄下降；斑马雀研究中只有大胆度与坚持度在两年内保持一致）。

**结论**：差异化不在「维度更科学」，而在**把 15 维向量变成一个可比较的量**——
从而解锁三种竞品结构上做不到的比较：**与过去的自己比、与另一只宠物比、与同品种基线比**。

赛道比预想拥挤，**最近的一个对手必须正面对标**。

| Dogality Test | — | 4 | 16 | 直译 | 自称「非科学验证」 |

**三点判断**：

1. **「用行为学维度」本身已不是空位** —— pawsona 已经占了先手，而且它的四轴（社交性 / 探索性 / 合作性 或 意志力 / 情绪性 或 敏感度）选得比我们早一轮的直觉更接近学术共识。**我们不能靠这一条赢。**
2. **全行业的主流分辨率是 4 维** —— 16 型、4 字母代码、可截图分享，这套「记忆负担低」的取舍是对的，也是我们要保留的。但 4 维丢掉了最有价值的组合信息：**「黏主人但怕生人」在 4 维里会被压成一个平均分。**
3. **跨物种比较是全行业的空白** —— 竞品的「契合度」要么是人和宠物比（跨物种量表相减，方法不成立），要么是同类两个类型比（离散、粗）。**没有一个用连续行为向量做跨物种/同物种的行为级对照。**

## 5. 差异化支柱（四条，每条都必须能被验收）

### 支柱一：15 维，且每维可溯源到论文的具体条目

- 每维对应**一篇论文里的一个具体因子或条目**，不是「参考了某研究」。
- 公开**维度出处页**：每个维度列出论文出处、原始条目、我们为什么这样翻译。
- 与竞品的区别不是「我们有 15 维」，是**「我们的 15 维每一维都能指回原文」**。

### 支柱二：猫狗分轴，各自的行为学基础不共用

猫和狗的行为学基础不同（猫是独居猎手、狗是群居物种），维度相同但**行为锚点不同**：猫的 D8 是「对同类猫」，狗的 D8 是「对同类狗」；猫的 D11 更偏气味标记与资源守护，狗更偏个人空间与护食。**题库完全独立，维度框架可复用。**

### 支柱三：压力信号独立成轴，且只做转介

赫尔辛基 2021 的原始结论明确指出：**乱尿/乱便（litterbox issues）与过度舔毛（excessive grooming）不是人格特质，而是压力敏感度的指标。**

多数竞品（以及市面上的 AI 生成报告）把这两项混进人格维度，**这是把病理指标当性格**。我们把它们单独做成一个**压力指数**（0–100），不参与类型匹配、不改变人格分，只输出一句克制的提示并转介给专业人士。

> 这条既是学术正确，也是最硬的合规护城河 —— 竞品都在往「行为建议」里夹带兽医判断，我们明确不做。

### 支柱四：15 维向量 = 可比较的量，解锁三种比较

这是产品真正的差异点，也是竞品结构上做不到的：

| 比较 | 玩法 | 学术依据 | 竞品能否 |
|---|---|---|---|
| **纵向** | 同一只猫，隔几个月复测 → 变化轨迹（哪几维动了、往哪动） | Turcsán 2009 年龄效应；斑马雀两年稳定性研究 | ❌ 只说「建议定期复测」，没有 diff |
| **横向** | 两只宠物的 15 维向量算距离 → **行为级摩擦预警**（不是类型配对） | DPQ 攻击性/恐惧性因子；Volhard 领地行为 | ❌ 只有离散类型配对 |
| **横切** | 与同品种的行为基线对照 | 赫尔辛基 26 个品种组；Turcsán 14004 只狗 | ⚠️ 只有「品种倾向」文字，无量化 |

**摩擦预警**长这样（示例，非最终文案）：

> 你家两只猫的**护食强度**都偏高（都到 H 档）。
> 这是一只猫在家庭里最常见的冲突源 —— 建议：**分食盆、固定餐位、观察进食顺序**。
> （这不是行为诊断。如果出现实际打斗或拒食，请咨询兽医或行为专业人士。）

具体到**哪一维冲突、给什么可执行动作**，而不是「两只猫可能不合」。

## 6. 测量框架

### 6.1 人格轴：5 模型 × 3 维 = 15 维

每维三档：**L（低）/ M（中）/ H（高）**。

| 模型 | 维度 | 低 ← → 高 | 学术出处（猫 / 狗） |
|---|---|---|---|
| **M1 应激与安定** | D1 大胆度 | 躲着走 / 观察后靠近 / 主动凑近 | 赫尔辛基「Fearfulness」反向 · Turcsán「boldness」 |
| | D2 惊惧敏感度 | 雷声无反应 / 一惊一乍 / 炸毛躲藏 | 赫尔辛基「Fearfulness」 · DPQ「Fear of Handling/Sound」 |
| | D3 恢复力 | 半天回不来 / 几分钟 / 一惊即过 | Volhard「Stability」 · BreedTools「Recovery」 |
| **M2 活力与探索** | D4 日常活动量 | 整天睡 / 固定玩闹时段 / 停不下来 | 赫尔辛基「Activity/playfulness」 · DPQ「Excitability」 |
| | D5 新奇探索欲 | 先躲 / 闻一闻 / 立刻拆扑 | 斑马雀 exploration · DPQ「Active Engagement」 |
| | D6 专注持久度 | 玩两下就走 / 熟悉的事能做完 / 咬着不放 | 斑马雀 persistence · DPQ「Active Engagement」 |
| **M3 社交** | D7 对人依恋亲近 | 你回来它照旧睡 / 会回应 / 时刻踩奶 | 赫尔辛基「Sociability to humans」 · DPQ「Companionability」 |
| | D8 同类社交 | 见同类炸毛 / 观察后共处 / 主动凑过去 | 赫尔辛基「Sociability to cats」 · DPQ「Aggression to dogs」反向 |
| | D9 社交主动性 | 客人来就躲 / 观望 / 第一个冲过去 | 赫尔辛基「Sociability to humans」 · DPQ「Social attraction」 |
| **M4 自主与领地** | D10 独立自主 | 贴着人走 / 你走它也待着 / 大部分时间自己待 | DPQ「Nonsocial fear」反向 · 猫的独立性 |
| | D11 领地与护食 | 资源被碰就走 / 会警告 / 死死护住抢食 | 赫尔辛基「Aggression to humans」 · DPQ「Situational aggression」 |
| | D12 变动耐受 | 换家具就乱 / 适应一两天 / 搬到哪都照样吃睡 | 赫尔辛基：环境反复变化是猫的压力源 · DPQ「adapts easily」反向 |
| **M5 情绪与应对** | D13 易激惹度 | 被冒犯会走开 / 会瞪会哼 / 咬抓扑 | 赫尔辛基「Aggression to humans」 · DPQ「General aggression」 |
| | D14 挫折耐受 | 得不到就放弃 / 试试就放弃 / 反复尝试叫扒砸 | 动物福利研究：挫折诱发攻击与 redirected aggression |
| | D15 冲动性 | 先观望很久 / 犹豫后行动 / 立刻扑抢冲 | Feline Five「Impulsiveness」 · Volhard「Elevation」 |

**设计取舍（写在这里，因为它们决定了出题）**：

1. **boldness 拆成 D1 + D2 + D3 三维。** boldness 与 neophobia 在学术上是部分独立的（斑马雀两年期只有 boldness 与 persistence 保持一致）；Volhard 与 BreedTools 本就把惊跳反应（Stability）与恢复速度（Recovery）分开测量。合成一维会丢信息。
2. **D7 / D8 / D9 三分（对主人 / 对同类 / 对陌生人）。** 猫最具画面感的画像就是「黏主人但怕生人」——合成一个「社交性」维度，这个特征直接消失。
3. **D8 必须给单宠家庭兜底场景**（「在宠物医院遇到同类时的反应」「小区里遇到同款」），否则单宠用户无法作答，题目就废了。
4. **15 维 ID 与名称猫狗共用，行为锚点按物种分开存。** 猫锚点写在 `content/types.json` 的 `dimensions`；狗锚点写在 `content/dimensions-dog.json`，15 维各 2 条（L / H），共 30 条（M 档不单独写文案）。结果页、维度出处页、类型库统一按物种读取锚点，不共用猫的 L / M / H 例句。

### 6.2 压力信号轴（独立，不参与类型匹配）

| 物种 | 指标 | 出处 |
|---|---|---|
| 猫 | 乱尿 / 乱便、不当位置排泄 | 赫尔辛基 2021「Litterbox issues」 |
| 猫 | 过度舔毛 | 赫尔辛基 2021「Excessive grooming」 |
| 狗 | 分离相关表现（独处时破坏、持续吠叫） | 犬分离相关行为文献 |
| 狗 | 过度舔咬自身 / 无明确诱因的重复行为 | 犬重复行为文献 |

**规则（硬约束）**：

- 压力指数**不进入 15 维向量**，因此**不参与类型匹配、不改变人格类型**。这保证了类型匹配公式的最大距离仍是 30，算法不被污染。
- 输出**只有两档引导**：`正常范围` / `建议关注`。
- 「建议关注」的文案**只指向专业人士**，不给原因推断、不给处置方案、不给程度判断。

> ⚠️ 这两档之间的措辞尺度，是这个项目最容易被写错的地方。评审必须逐句过。

### 6.3 计分与匹配算法

**沿用 SBTI 的算法外壳**（框架与内容分离，便于量产题库分册）：

```
每题 3 个选项 → 1 / 2 / 3 分（反向题用 points = 4 - p 翻转）
每维 2 题 → 分数和 2-3 记 L / 4 记 M / 5-6 记 H
15 维 → L=1, M=2, H=3 的数值向量
与类型模板逐维求曼哈顿距离 → 最小者胜
similarity = max(0, round((1 - distance / 30) * 100))
```

> 15 维 × 每维最大差 2 = 最大距离 30，与 SBTI 完全一致，公式可原样照抄。

**兜底与隐藏**：

- **兜底型**：最高相似度 < 60% → 触发兜底型（对应 SBTI 的 HHHH 机制）。语义是「你太特别，现有模板装不下」——**这是特性不是失败**，文案必须正面处理。
- **隐藏型**：由**规则触发**而非条件题，触发条件写死在我们自己的维度上（这是可溯源差异化的产物，竞品抄不走）。**且必须未精确命中任一 16 型模板**（与最匹配模板距离 ≥ 1）——精确命中时以 16 型为准，保证 16 型可达：
  - 猫册：**纸箱工程师** —— D5 新奇探索欲 = H 且 D6 专注持久度 = H 且 D4 日常活动量 = H
  - 狗册：**飞盘永动机** —— D4 = H 且 D6 = H 且 D14 挫折耐受 = H
- **并列处理**：距离相同时，优先取**精确匹配维度更多**的类型；仍相同则保留先遍历到的模板（序号较小者）。

### 6.4 类型生成方法（不靠手拍）

16 型不是「拍脑袋想 16 个名字」，方法是**在候选向量空间里做最远点采样**：

1. **候选池**：15 维各取 L/M/H 的全部合理组合，人工剔除生物学上不可达的组合（如 D1=胆大 H + D2=惊惧敏感 H + D3=恢复力 L 在物种本位上不常见）。
2. **种子集**：极端原型 —— 全 L、全 H，以及四个单模型极端（全高 M1、全高 M2……）。
3. **贪心扩张**：每次加入「到已选集合最小曼哈顿距离最大」的候选，直到 16 个。
4. **人工命名**：给每个向量起名 + 一句话钩子 + 相处建议。

**结果**：类型之间在维度空间上**分布均匀**，不会出现「16 型里有 9 型其实是同一只猫」的重叠 —— 这是手写类型库的通病（现有竞品的 16 型普遍重叠严重）。

### 6.5 命名与文案规范

- **代码**：4 字母大写，取自行为词（如 `BRISK` 轻快、`GUARD` 守界），**不用 MBTI 式字母**。
- **中文名**：必须是从**具体行为**长出来的短语，不是形容词。
  - ✅ 「纸箱工程师」「守饭盆的那位」「踩奶到天亮」
  - ❌ 「黏人小甜心」「高冷小王子」（这是拟人，且带褒贬）
- **钩子**：一句话，必须是主人**一眼能对上自己家那只**的具体场景，不是形容词堆砌。
- **相处建议**：具体动作，不是「多陪伴它」这种废话。
- **禁用词**：最、第一、绝对、一定、治愈、治愈系；以及任何对动物的品质评判。
- **类型文案全部自写**，不抄 SBTI 的 27 型、CBTI 的 18 猫型、CMBTI 的 16 猫格、HeroMama 的职业志向。中文名与英文代码均需查重。

## 7. 内容规范（题型契约）

这一节是**出题的直接依据**，也是内容质量的护栏。

| 项 | 规格 |
|---|---|
| 题量 | 30 题（15 维 × 2 题）+ 4 题压力信号 |
| 选项 | 3 个，每个映射 1/2/3 分 |
| 维度归属 | **每题只服务一个维度** —— 跨维度会污染计分 |
| 反向题 | `points = 4 - p` 翻转。全卷约 1/6（DPQ 用 reverse-coded 中和「全选可爱项」的赞许偏差） |
| 选项措辞 | **必须中性** —— 不写「黏人可爱 vs 冷漠孤僻」这种带褒贬的成对选项 |
| 场景约束 | 只写**可观察行为**（「你出门后前 30 分钟它在哪」），不写内心推断（「它是不是把你当妈妈」）——后者是投射，不是测量 |
| 时间锚定 | 行为学问卷问的是**长期稳定倾向**，题面须写明「按它平时的样子」，不写「今天」 |
| 分布要求 | 每维 2 题；反向题每维至多 1 题；单宠家庭友好（D8 必须有兜底场景） |

**维度出处页**（公开页面）：每个维度列出论文出处、原始条目、翻译理由。这是支柱一的交付物，不是文档附件。

| `/` | 首页：猫册 / 狗册测试入口、类型库、维度出处、关于与隐私；有历史记录时按物种显示轨迹入口 |
| `/test` | 猫册测试流（30 题 → 4 题压力信号 → 结果）；`?species=dog` 走狗册测试流 |
| `/result/[code]` | 猫册结果页：类型 + 相似度 + 15 维雷达 + 压力指数 + 相处建议 + 分享卡 |
| `/dog/result/[code]` | 狗册结果页，结构与猫册相同，数据按物种读取 |
| `/library` | 类型库：当前物种全部 16 型；`?species=dog` 读狗册文案 |
| `/compare` | 双宠对照：输入两只宠物的结果 → 摩擦预警；默认同物种，`?species=dog` 走狗册 |
| `/trace` | 纵向轨迹：同一只宠物的历次结果 → 变化 diff；`?species=dog` 只看狗册记录 |
| `/dimensions` | 维度出处页（公开，支柱一）；`?species=dog` 显示狗锚点与出处 |
| `/about` | 方法论、免责声明、数据与隐私 |

**物种路由约定（唯一结论）**：

- **猫册是默认物种**：不带物种参数时，`/test`、`/result/[code]`、`/library`、`/trace`、`/compare`、`/dimensions` 一律按猫册处理。
- **狗册走独立前缀或显式参数**：结果页固定为 `/dog/result/[code]`；其他页面用 `?species=dog`。
- **旧分享链接不迁移**：已发出的 `/result/<code>` 永远按猫册解析，不能因为狗册上线而被重新解释；狗册结果只从 `/dog/result/<code>` 生成。

### 8.2 测试流

- 纯客户端，无账号，无服务端状态，**答案不出浏览器**。
- 题目随机打乱（避免连续同维度引导），**每题的选项顺序也打乱**；选项只改变显示顺序，计分仍按原始下标（反向题 `4 - p` 语义不变）。
- 打乱顺序随进度一起持久化：刷新或重进沿用本轮已生成的顺序，不重新洗牌；进度结构变化时升级 key 并丢弃旧进度，不做静默兼容。
- 中途可退出，**进度存 localStorage**，回来接着答。
- 结果 URL 用 **3 进制 / base36 自解码编码**（可分享、可复现、不可反推答案），实现见 §19.3；不落个人数据。
- **物种由入口决定**：`/test` 默认猫册，`/test?species=dog` 走狗册；题目、压力题与文案都从对应物种的数据集读取，不交叉。
- **进度与跳转带物种**：进度 key 猫册为 `pawscribe-progress-v3`，狗册为 `pawscribe-progress-v3:dog`；结果跳转猫册 `/result/<code>`、狗册 `/dog/result/<code>`。
- **狗册内容未就绪时（当前猫狗两册均已就绪）**：`/test?species=dog` 与 `/dog/*` 返回「狗册准备中」状态页，**不展示占位题目或假文案**。

### 8.3 结果页结构

1. **类型卡**：4 字母代码 + 中文名 + 钩子（兜底型 / 隐藏型无代码，以「兜底型」「隐藏型」标签代替，见 §17.3）
2. **相似度**：百分比 + 匹配类型（与 16 型模板逐维距离最小者）
3. **15 维雷达**：按 5 模型分色，与 SBTI 的雷达图一致
4. **压力指数**：0–100 + 克制提示（若 ≥ 关注线）
5. **相处建议**：3 条具体动作
6. **品种参考**：**定性**描述 + 标注论文与样本量（**不编造百分位** —— 我们没有常模数据）
7. **分享卡**：Canvas 生成 1200×630 PNG，一屏展示结果 + 雷达缩略 + 短链接

> **品种参考现状**：当前文案为定性描述并标注「无常模数据」；逐型论文与样本量尚未补全，属于内容待补项。

> 结果页按物种读取类型文案、维度锚点与压力文案：猫 `/result/[code]`，狗 `/dog/result/[code]`；页面结构不变，数据来源不同（§10.3）。

### 8.4 三种比较的交互

- **双宠对照** `/compare`：两只宠物各 30 题 → 输出 15 维距离 + **列出具名冲突维度**（如「护食强度双双偏高」）+ **D11 领地与护食**的可执行建议 + 合作度百分比；其他冲突维度只展示维度名与「双方均为 H 档」。
  - 合作度 = `round((1 - d / 30) * 100)`，其中 `d` 为两只宠物 15 维向量的曼哈顿距离。这是**行为距离换算**，不是心理学量表分，不具常模含义。
  - **物种参数**：`?species=dog` 表示两侧都是狗册；也接受 `?speciesA=cat&speciesB=dog`。两侧物种不同时**明确拒绝**，提示「跨物种不能做维度距离对照」，**不计算合作度、不输出建议**；默认两侧同物种（猫）。猫与狗的锚点、题库各自独立，向量不在同一测量尺度上，不做「维度距离假装合作度」。
  - 压力信号不进入比较（见 AGENTS 第 2.2 节红线）。
  - 建议覆盖边界（v1）：只对 **D11 领地与护食**提供具名建议；其他冲突维度只展示维度名与「双方均为 H 档」，不提供通用建议。这是有意为之的内容边界，不是遗漏。
- **纵向轨迹** `/trace`：同一只宠物的多次结果 → 逐维 diff（箭头 + 变化幅度）+ 一句总结（「它这半年更敢接近陌生人了，社交主动性从 M 升到 H」）。
  - 基线：默认「最新 vs 上一条」，允许选择任一更早记录作为基线；15 维全展示，`↑ / ↓ / —`，档位跨两档（如 L→H）额外标注「跨两档」。
  - 总结：只列变化维度，最多 3 条，按变化档数从大到小排序；0 变化写「和上次相比没有变化」；只描述变化，不做因果解释（§13）。
  - 空状态与入口：0 条显示说明与开始测试 CTA；1 条展示该条记录并提示「再测一次才能看变化」；≥2 条才输出 diff。结果页在 ≥2 条时显示入口。首页轨迹入口**按物种分别判断**：某物种有记录才显示对应入口（猫 `/trace`，狗 `/trace?species=dog`）；仅猫记录时保持原「历史轨迹」入口，仅狗记录时只显示「狗册轨迹」，两册都有时两个入口都显示，不会点进另一物种的空页。
  - 清空：`/trace` 的「清空本册」只清空当前页面对应物种的记录，**另一物种的记录保留**；清空后当前页回到该物种的空状态。
  - 分享与隐私：分享卡 / URL 只带最新单次结果，历史永不出现在分享物；历史不导出、不上传；页面显著标注「历史仅存本机」。
  - **按物种分组**：diff 只允许同一 `species + petId` 的记录；猫狗记录不混算，`?species=dog` 只展示狗册记录。
  - 历史的数据契约、身份、容量与降级规则见 §19.4。

### 8.5 传播机制

- **分享卡**是主传播单元：类型 + 钩子 + 雷达缩略 + 短链接。
- **反向邀请**：结果页直接提供「测我家另一只」，生成双宠对照链接（两个 base36 结果编码，见 §19.3）。
- **结果链接分享**：结果页「分享结果」优先调用系统分享（`navigator.share`，标题 + 一句文案 + 结果 URL）；不可用或失败时降级为复制链接，成功与失败都有可见反馈。分享内容只含结果 URL（15 维向量），不含答案、压力分与历史记录；文案不暗示诊断。**URL 按物种构造**：猫 `/result/<code>`，狗 `/dog/result/<code>`。
- **抓取预览**：猫 `/result/[code]` 与狗 `/dog/result/[code]` 各自用无状态 `generateMetadata` 按 code 生成 title/description 与 og/twitter 标签；文案来自对应物种的类型文案与锚点，标题带物种语境；非法 code 返回通用兜底 metadata。只做纯计算，不落盘、不写服务端状态。
- **不做的**：不设排行榜、不做签到、不做账号、不做付费墙。**所有结果永久免费完整可见** —— 这是我们与「基础免费 + 完整报告付费」（mypetvillage、Pup Personality）明确对立的选择。

## 9. 合规与红线

### 9.1 绝对不做

| 红线 | 说明 |
|---|---|
| **不做兽医建议** | 不给治疗、用药、手术、绝育时机建议。压力指数只转介。 |
| **不做行为诊断** | 不使用「诊断」「异常」「障碍」「病症」等词描述测试结果。 |
| **不给危险行为定性** | 咬人、扑人、护食等只能描述为**行为强度**，且必须附「若造成伤害请咨询专业人士」。 |
| **不收集个人信息** | 无账号、无邮箱、无手机号。答案与结果只存本地。 |
| **不训练「服从」** | 建议不得以「压制」「制服」为目标 —— 这是把动物福利当手段。 |
| **不给单只宠物下永久结论** | 页面必须显著标注「这是行为倾向的快照，不是永久标签」，并引导复测。 |

### 9.2 必须显著标注

- 「本测试基于日常行为观察，仅供自我了解与参考，**不构成兽医学或动物行为学诊断**。」
- 「毛孩的行为会随年龄、健康状况与环境变化，**建议定期复测**。」
- 「若你或宠物存在紧急风险或健康问题，请及时寻求专业机构与持证人士帮助。」

> 这三条的措辞与位置统一，至少出现在结果页、维度页与关于页；新增页面不得自创不同措辞。

## 11. 成功标准（可验证）

**内容质量（最关键，先于流量）**

| # | 标准 | 判定方式 |
|---|---|---|
| 1 | **复测一致性（上线后研究里程碑，不是发布门禁）**：10–15 只猫间隔 ≥7 天填两遍，≥10/15 维两次结果一致 | 上线后自建小样本对照（依据 DPQ 的 test–retest 思路）；同时记录每维变化方向与当时的压力分，用来区分「题不稳」与「猫真变了」 |
| 2 | **三档分布健康**：每维的 L / M / H 占比每档 ≥15% | 结果分布统计，防止模板塌缩 |
| 3 | **类型覆盖**：16 型中至少 8 型累计覆盖 90% 用户 | 结果分布统计 |
| 4 | **类型可分辨**：任意两型的曼哈顿距离 ≥4 | 生成时校验（最远点采样的直接产物） |
| 5 | **维度出处完整**：15 维全部有论文出处与原始条目映射 | 人工评审 + 维度出处页上线 |

**产品体验**

| # | 标准 |
|---|---|
| 6 | 开始 → 完成 ≥70% |
| 7 | 结果页分享率 ≥25% |
| 8 | 全流程服务端调用 = 0 |
| 9 | 压力提示文案经兽医/行为学专业人士评审通过 |

> 标准 1 是这个项目**最诚实也最脆弱**的一环：15 维有学术依据，但「主人自评」在娱乐测试语境下的信效度**从未被验证过**。它按下不表的部分（复测信度）改为上线后持续跟踪的研究里程碑，不阻塞发布。

> **发布门禁（2026-11-03 调整）**：能否发布不看标准 1，看三条——
> ① **CI 全绿**：`.github/workflows/ci.yml` 的 `typecheck` / `cli:validate` / `test` / `build` 全部通过；
> ② **关键路径冒烟**：按人工清单逐条走通（首页 → 猫册/狗册 30 题 + 4 道压力题 → 结果页 → 类型库 → 维度 → 轨迹 → 对照 → 分享下载），冒烟**暂未自动化**；
> ③ **30 题完成率可观测**：标准 6 的完成率有可读取的统计口径，不是凭印象判断。

> 验收记录（2026-11-03）：§11 的 1–9 项目前均未形成可复核的验收记录；本文只定义标准，不声称已达标。

### 关于第 4 项的风险说明（重要）

纯免费纯传播的商业路径有两条，都不轻松：

### 16.4 两档文案

压力指数 0–100：4 题各按 0/50/100 计分，四项求和后除以 4 并四舍五入（即取均值），**不是四项累加**；**0–49 为正常范围，50–100 为建议关注**。

**正常范围**：你的猫目前没有明显的压力信号。继续保持稳定的日常作息和环境，定期观察它的行为变化。

**建议关注**：你的猫最近表现出一些压力信号。这些信号可能与环境和日常变化有关，也可能与健康状况有关。建议你咨询兽医或动物行为专业人士，获得针对性的建议和帮助。

> 两档文案均不含「诊断 / 异常 / 障碍 / 病症」等词，不给原因推断与处置方案；「建议关注」只指向专业人士。

### 17.3 隐藏型与兜底型

- **隐藏型「纸箱工程师」**：触发条件 = D4 日常活动量 = H 且 D5 新奇探索欲 = H 且 D6 专注持久度 = H，**且未精确命中任一 16 型模板**（与最匹配模板距离 ≥ 1）。精确命中时返回该模板型，不触发隐藏型。
  - 示例向量：`LLLHHHLLLLLLLLL` 精确命中 DART，返回 DART；`LMLHHHLLLLLLLLL` 与之距离 1，触发隐藏型。
  - 文案：纸箱工程师——「它对纸箱的热爱不分场合，任何纸箱都要钻进去，待在里面不出来」。
  - 相处建议：1. 准备几个不同尺寸的纸箱，满足它的探索欲；2. 纸箱里放零食或猫薄荷，增加趣味；3. 定期更换纸箱位置，保持新鲜感。
- **兜底型**：触发条件 = 最高相似度 < 60%。
  - 文案：「你太特别，现有模板装不下」——这是特性不是失败。
  - 相处建议：1. 你的猫可能同时具备多种矛盾特质；2. 建议关注它在具体场景下的行为，而非类型标签；3. 可以定期复测，观察变化。

### 19.3 结果 URL 实现

**问题**：§8.2 说结果 URL 用「内容哈希」，但纯哈希（如 sha256）前端无法反推结果，与「无服务端」矛盾。

**修正**：结果 URL 改用 **3 进制 / base36 自解码编码**。

- 15 维向量（每维 L/M/H = 0/1/2）用 3 进制编码为整数，再转 base36 字符串；**最长 5 位，不补前导零**（实际长度 1–5 位）。
- 位数推算：`3^15 = 14,348,907`；`36^4 = 1,679,616 < 3^15 ≤ 36^5 = 60,466,176`，因此 base36 至少 5 位、且 5 位足够。全 H（`3^15 - 1 = 14,348,906`）编码为 `8JJOQ`，全 L 为 `0`。
- 前端自解码：`/result/8JJOQ` → 解码为全 H 的 15 维向量 → 匹配类型 → 渲染结果页。
- **无需服务端**，可分享、可复现。
- URL 只含维度分，不含题目答案 → 满足「不可反推答案」。
- **物种不进编码**：`code` 只承载 15 维向量，不携带物种；物种由路径承载（猫 `/result/<code>`，狗 `/dog/result/<code>`）。同一向量在猫狗两册可得到不同的类型文案，而链接语义不会被 code 本身混淆。
- 示例：`/result/0`（全 L）、`/result/8JJOQ`（全 H）；狗册对应 `/dog/result/0`、`/dog/result/8JJOQ`。

**编码实现**（伪代码）：

```
编码：vector = [0,1,2,...]  // 15 维，每维 0/1/2
      num = sum(vector[i] * 3^i for i in 0..14)  // 3 进制转整数
      code = base36(num).toUpperCase()  // 转 base36
解码：num = base36Decode(code)
      vector[i] = (num / 3^i) % 3
```

### 19.4 `/trace` 存储与身份修正

**问题**：§8.4 只定义了 `/trace` 的输出形态，未定义历史存什么、存在哪、如何区分宠物、如何清理。直接实现会让代码成为事实规范。

**修正**：

- **存储**：`localStorage` key 为 `pawscribe-history-v1`，结构 `{ version: 1, records: TraceRecord[] }`，`records` 按新→旧排列。
- **记录**：`{ id, species, petId, petLabel?, code, vector, testedAt }`；`vector` 为 15 维 0/1/2，`testedAt` 为 ISO 时间。存 `vector` 使 diff 不依赖结果编码；存 `species` 防止猫狗混算。
- **身份**：v1.1 单宠单档案；存储内 `petId` 命名空间化为 `<species>-default`（`cat-default` / `dog-default`），可选 `petLabel`；历史仅限当前浏览器 / 设备，不跨端。多宠切换推迟到 v3。同一浏览器多人使用时仍按单档案处理，这是 v1.1 的明确限制，不是缺陷。
- **旧数据迁移**：已存在的 `pawscribe-history-v1` **不升 key**。读取时把旧记录的 `petId = 'default'` 按 `species` 改写为 `cat-default` / `dog-default`，内存中返回迁移后的结果，写入时一并写回。旧历史不会被静默丢光，也不需要用户手动清理；若写回失败（隐私模式、配额满），读取仍返回迁移后的内存数据，下次写入再尝试。
- **容量与清理**：按 `species + petId` 计数，每个组合最多 20 条，猫狗互不挤占；超出删除该组合最旧的记录；同一组合 24 小时内相同 `code` 合并为最新一条；提供删除单条与**按物种清空当前册**（另一物种记录保留）；不做 TTL。
- **压力分存储**：`sessionStorage` key 为 `pawscribe-stress:<species>`（`pawscribe-stress:cat` / `pawscribe-stress:dog`），避免猫测后打开狗结果读到猫的压力分。旧 key `pawscribe-stress` **只作为猫册的回退读取来源**：猫册结果页在没有新 key 时读取并迁移到 `pawscribe-stress:cat`；狗册不读旧 key，直接视为无压力分。
- **降级**：`localStorage` 不可用（隐私模式、配额满）或解析失败时，读取返回空历史，写入返回失败原因，页面提示但不崩溃；`version` 不等于 1 时按空历史处理并允许重写。
- **红线**：历史只存维度向量与时间，不含答案与压力分；不上传、不导出。
